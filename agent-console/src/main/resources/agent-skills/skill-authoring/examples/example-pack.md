# 成品样例：把"周报生成"做成技能包

下面是一个合规技能包的完整形态，用于对齐包结构与 description 写法。
**样例中的技能名、字段、话术全部是虚构示例**，不要照抄进用户需求。

## 目录

```text
weekly-report/
├── SKILL.md
├── templates/weekly.md
└── examples/weekly-sample.md
```

## 根 SKILL.md

```markdown
---
name: weekly-report
title: 周报生成
category: 文书写作
description: 把一段时间内的工作要点整理成结构固定的周报。当用户给出本周／上周的工作条目、进度与下步计划，要求"写成周报／汇总成本周工作汇报"时使用：先核对必填要点，再按模板成文。本技能只提供流程与文体，不扩充工具权限。
---

# 周报生成流程

把用户口头的工作条目整理成一篇结构固定的周报。

## 输入与产出

- 输入：时间范围、主要工作条目、完成情况、遇到的问题、下步计划。
- 产出：Markdown 周报，含"本周工作""问题与风险""下周计划"三节。

## 执行步骤

1. 对照 templates/weekly.md 的字段清单，逐项判定已有／缺失。
2. 缺失要点一次只问一个（用 ask_user），不代填、不推测。
3. 字段齐后先给大纲，用户确认再成文。
4. 按模板逐节写入草稿，写完通读自查。

## 产出契约

- 每节用二级标题，顺序与模板一致；工作条目用"事项—进度—结论"三列表格。
- 日期统一 YYYY年M月D日；材料没给时间就追问，不留空。

## 边界

- 材料只来自用户对话输入，不检索库内文档。
- 不扩充工具权限。
```

## 要点回看

- 根文件夹名 `weekly-report` 与 `name` 一致，且只含合法字符。
- `description` 写清了"做什么 + 何时触发"，因为它是模型默认唯一看得到的部分。
- 正文不出现 shell／脚本指令，只引用已注册的工具名（此处为形态示意）。
