## 2026-10-27 透视比率度量两腿各配聚合（分母腿 max 服务「目标值」口径，达成率=sum(实际)/max(目标)）

**状态：本地改动，未提交——框架 core 改动 push 前须经用户 review**。
**动因**：经营项目达成率报表＝明细行上挂区域/部门目标（目标在组内恒定）。ratio 分母若与分子同用 sum，目标被组内行数放大（区域下 N 个项目 ⇒ 分母 ×N）。用户裁定不做「再加一个 sum/max 变体」，一次把两腿做成可配聚合——此后 sum/avg、count 等组合全是配置不是代码。

### Fixed（机制扩展，非缺陷修复）
- `lowcode/forge/.../service/statistic/DriverStatisticSupportService.java` —— ratio 分支改调 `AdminStatisticPivotInf.buildRatioExpr`（两腿各按配置聚合、缺省 sum），普通度量改调 `buildAggExpr`，**删除本地重复的 `buildPivotAggExpr` 映射**——kernel/forge 两生成点的聚合语义由「注释声称对齐」变为字面上同一份代码。
- 同机制 kernel 侧（除法壳与模型的正源在 kernel，路径列出备查）：
  - `base/kernel/.../vo/portal/statistic/PivotMeasure.java` —— 新增 `numeratorAgg`／`denominatorAgg`（可空，缺省 sum，老配置反序列化零变化）；
  - `base/kernel/.../controller/inf/statistic/AdminStatisticPivotInf.java` —— 新增静态件 `buildAggExpr`（聚合方式→SQL 映射，未知值回落 sum）、`resolveRatioLegAgg`（白名单 {sum,count,avg,min,max,countDistinct}，白名单外**拒收**——拼 SQL 层静默回落会把错数伪装成正常数字）、`buildRatioExpr`（除法壳：两腿各按配置聚合后相除，除零回落 NULL）；`buildPivotAgg` 的 ratio 分支改走 `buildRatioExpr`。
- 前端（erp-view `src/framework` 子模块，未提交）：`apis/portal/table.ts` 度量类型补两字段；`PortalTableBasicPane.vue` ratio 行分子/分母后各加腿聚合下拉（缺省 sum），解析老配置补默认值，落库防呆仅 ratio 行带腿聚合。

### Impact / 验证
- 新增 `base/kernel/src/test/.../AdminStatisticPivotRatioLegTest.java` **5/5 PASS**，`DriverStatisticPivotRatioTest` 扩至 **7/7 PASS**（`mvn -pl lowcode/forge -am -Pdevelopment,!public-snapshots -Dtest=… test`；Reactor 8 模块全 SUCCESS，surefire 产物 10-27 20:34/20:36 本轮生成）：①缺省腿＝老产物不变——kernel 对 `buildRatioExpr` 精确等值案＋forge「显式 sum/sum 与不配置逐字节相等」案；②分母 max 产物 `sum(case when …)/nullif(max(case when …),0)`，且无聚合嵌套；③白名单六聚合映射正例（countDistinct/count/avg）；④`median` 白名单外拒收（kernel/forge 各一负向案）；⑤旧 4 案（双腿 case when、无条件退化、ratio 与 sum 共存、缺分子拒绝）全保留＝回归针。
- 前端 eslint 净；vue-tsc 306 条＝基线同数且改动文件不在错误清单。
- **同版本边界**：新前端配置（带腿聚合）发老后端会被 Jackson 静默忽略按 sum/sum 算（`hideZero` 先例同形）⇒ **前后端须同版部署**，与 ratio 既有要求一致；老配置（无腿聚合字段）跑新后端零变化。
