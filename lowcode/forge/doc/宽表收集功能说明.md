# 宽表收集功能说明

## 一、功能概述

宽表收集功能将动态表单（EAV 模型）中分散的字段数据，汇聚到一张物理宽表中，便于后续统计分析、Portal 展示和数据导出。

核心能力：
- 动态建表（根据勾选字段自动生成 DDL）
- Portal 列配置自动生成（含字典字段映射）
- 数据收集（EAV → 宽表行）
- 增量/全量同步策略
- 异步收集 + 进度条

## 二、分层架构

```
┌─────────────────────────────────────────────────────────────┐
│  框架层 (core/forge)                                         │
│                                                             │
│  职责：建表、Portal列生成、EAV数据读取、INSERT宽表、进度管理  │
│                                                             │
│  核心类：                                                    │
│  - FormWideTableManager      生命周期管理（DDL/Portal/配置）  │
│  - FormWideTableCollector    同步收集（增量/全量）            │
│  - WideTableCollectAsyncService  异步收集 + 进度上报          │
│                                                             │
│  对外接口（由业务层实现）：                                    │
│  - WideTableBusinessContextProvider  "数据从哪来"            │
│  - WideTableConfigProvider           "固定列长什么样"        │
└─────────────────────────────────────────────────────────────┘
                         ▲ 实现
┌─────────────────────────────────────────────────────────────┐
│  业务层 (mpbe-manage)                                        │
│                                                             │
│  职责：定义数据来源、筛选条件、固定业务列                      │
│                                                             │
│  实现类：                                                    │
│  - EvalWideTableContextProvider  查 eval_enterprise_history  │
│  - EvalWideTableConfigProvider   定义企业/产品/批号等固定列   │
│  - WideTableContextInjection     启动时注入 Provider          │
│  - WideTableCollectJob           定时任务（每小时增量同步）    │
└─────────────────────────────────────────────────────────────┘
```

**设计原则：框架定规则，业务填内容。新项目接入只需实现业务层，框架层完全不改。**

## 三、两个核心接口

### 3.1 WideTableBusinessContextProvider（数据从哪来）

```java
public interface WideTableBusinessContextProvider {
    // 根据 historyId 获取单条业务上下文
    WideTableBusinessContext getContext(String historyId);

    // 查询指定表单下待收集的记录列表（排除已收集的）
    List<WideTableBusinessContext> getSubmittedHistories(String formId, List<String> excludeHistoryIds);
}
```

**业务层实现要点：**
- 筛选条件由业务决定（如当前项目：`status in (1, 3)` = 已提交 + 已通过）
- 返回的 `WideTableBusinessContext` 包含：historyId、enterpriseId/Name、productId/Name、versionNo、submittedAt、status

### 3.2 WideTableConfigProvider（固定列定义）

```java
public interface WideTableConfigProvider {
    List<WideTableFixedColumn> getFixedColumns();
}
```

**WideTableFixedColumn 字段说明：**

| 字段 | 说明 | 示例 |
|------|------|------|
| columnName | 物理列名 | `enterprise_name` |
| columnType | MySQL 类型 | `varchar(200)` |
| columnLabel | 显示名 | `企业名称` |
| portalFieldType | Portal 字段类型 | `PortalFieldDict.STRING.getValue()` |
| dictId | 关联字典（ENUM时用） | `APPROVAL_DICT` |
| contextKey | 上下文取值键 | `enterpriseName` |
| width | 列宽 | `150` |

**contextKey 是桥梁：** 框架通过 `context.getContextValue(contextKey)` 取值，不需要知道业务含义。

## 四、数据流

```
用户点"收集" / 定时任务触发
    │
    ▼
FormWideTableCollector.collect(configId)
    │
    ├─ 1. 读取 ConfigAttr（已配置的动态字段列表）
    │
    ├─ 2. 查 sync_log 获取已同步的 historyId（增量模式）
    │
    ├─ 3. 调 contextProvider.getSubmittedHistories(formId, excludeIds)
    │      → 业务层查业务表，返回待收集记录
    │
    ├─ 4. 对每条 context:
    │      ├─ 从 FormData 按 attributeId 读动态字段值
    │      ├─ 从 context 按 contextKey 取固定列值
    │      └─ DELETE + INSERT INTO 宽表
    │
    └─ 5. 写 sync_log（记录成功/失败）
```

## 五、同步策略

| 触发方式 | 方法 | 是否清空 | 说明 |
|----------|------|----------|------|
| 每小时定时 | `@Scheduled` → `collectAll()` | 不清空 | 增量收集新提交记录 |
| 编辑字段保存后 | 前端调 `reCollectAsync` | 清空 | DROP+CREATE 重建表 → 全量收集 |
| 手动点"收集" | 前端调 `reCollectAsync` | 清空 | 全量重收集（带进度条） |
| 手动"收集全部" | 前端调 `collectAll` | 不清空 | 增量收集所有 active 配置 |

**reCollect 全量重收集流程：**
1. 清除该 configId 的所有 sync_log
2. DROP + CREATE 重建物理表（确保列结构与最新配置一致）
3. 调用 `getSubmittedHistories(formId, [])` 获取全部记录
4. 逐条 INSERT

## 七、新项目接入指南

只需在业务层写 **2 个实现类 + 1 个注入类**：

### 步骤 1：实现 WideTableBusinessContextProvider

```java
@Service
public class MyContextProvider implements WideTableBusinessContextProvider {

    @Override
    public List<WideTableBusinessContext> getSubmittedHistories(String formId, List<String> excludeIds) {
        // 1. 通过 formId 找到关联的业务记录
        // 2. 筛选条件你自己定（如只收审核通过的）
        // 3. 排除 excludeIds（已收集的）
        // 4. 组装 WideTableBusinessContext 返回
    }

    @Override
    public WideTableBusinessContext getContext(String historyId) {
        // 根据 historyId 查单条上下文
    }
}
```

### 步骤 2：实现 WideTableConfigProvider

```java
@Service
public class MyConfigProvider implements WideTableConfigProvider {

    @Override
    public List<WideTableFixedColumn> getFixedColumns() {
        return Arrays.asList(
            new WideTableFixedColumn("dept_name", "varchar(200)", "部门名称",
                PortalFieldDict.STRING.getValue(), null, "deptName", 150),
            new WideTableFixedColumn("status", "varchar(10)", "状态",
                PortalFieldDict.ENUM.getValue(), "MY_STATUS_DICT", "status", 100)
        );
    }
}
```

### 步骤 3：启动时注入

```java
@Component
@RequiredArgsConstructor
public class MyWideTableInjection {
    private final FormWideTableCollector collector;
    private final FormWideTableManager manager;
    private final WideTableCollectAsyncService asyncService;
    private final MyContextProvider contextProvider;
    private final MyConfigProvider configProvider;

    @PostConstruct
    public void inject() {
        collector.setContextProvider(contextProvider);
        collector.setConfigProvider(configProvider);
        manager.setConfigProvider(configProvider);
        asyncService.setContextProvider(contextProvider);
        asyncService.setConfigProvider(configProvider);
    }
}
```

### 步骤 4（可选）：添加定时任务

```java
@Scheduled(cron = "0 0 * * * ?")  // 每小时
public void scheduledCollect() {
    formWideTableCollector.collectAll();
}
```

**框架层完全不用改。**

## 九、注意事项

1. **列名唯一性**：动态列名 = `字段拼音名_attributeId`（如 `sheng_chan_gong_yi_95`），避免同名字段冲突
2. **MySQL 行大小限制**：动态字段统一使用 `TEXT` 类型，避免超过 65535 字节限制
3. **dict_id 字段长度**：`varchar(200)`，兼容长字典 ID
4. **reCollect 会清空数据**：仅在字段配置变更或手动触发时使用，定时任务用增量 `collect`
5. **异步进度存储**：通过 `TokenService` 存入 Redis，key = `UPLOAD_PROGRESS_WideTableCollect`
