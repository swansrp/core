# 在线预览服务接入指南（kkFileView）

> 适用模块：`framework/core/oss`（参数与接口内置于此，所有引入该模块的项目共享）
> 组成：OSS 系统参数 `OSS_PREVIEW_URL` + 通用接口 `GET /web/oss/preview-url` + 前端动态渲染
> 特性：参数为 0（默认值，或空）时预览功能整体关闭；不同客户可配置各自的 kk 地址

## 0. 架构与原理

```
浏览器 ── GET /web/oss/preview-url ──► 后端（读 sys_config.OSS_PREVIEW_URL）
浏览器 ◄───── 地址前缀（空串 = 未开启）──┘
浏览器 ── window.open(前缀 + Base64(文件URL)) ──► nginx /kkfileview/ ──► kkfileview:8012
                                                        kk 服务端自行下载文件URL
                                                        → LibreOffice 转 PDF → 图片预览页
```

- kkFileView 纯 URL 模式，无 SDK：唯一要求是 **kk 容器能访问到文件的 http(s) 地址**（网盘场景为后端实时签发的短时效 inline 预签名地址，不会泄露长期凭证）。
- 转换产物缓存在 kk 容器数据目录，删除后访问会自动重新转换，无功能影响。

## 1. 配置 kkFileView（服务端部署）

### 1.1 启动容器

```bash
mkdir -p /data/kkfileview/file   # 缓存目录放数据盘（生产 zz 为 100G 数据盘挂载点）

docker run -d \
  --name kkfileview \
  -e KK_CONTEXT_PATH=/kkfileview \
  -p 8012:8012 \
  -m 2g --memory-swap 3g \
  --restart unless-stopped \
  -v /data/kkfileview/file:/opt/kkFileView-4.1.0/file \
  keking/kkfileview:4.1.0
```

要点：
- **`KK_CONTEXT_PATH=/kkfileview` 必须与 nginx 子路径一致**：kk 生成的预览页内所有绝对资源地址会自动带上该前缀，天然可经 nginx 访问（生产实测镜像 `keking/kkfileview:local`，同参数）。
- 挂载路径中的版本号目录（`/opt/kkFileView-4.1.0/file`）随镜像版本变化，以 `docker exec kkfileview ls /opt` 实际为准。
- 内存限制 `-m 2g` 防止转换任务挤占宿主机；`8012` 不开放公网安全组，仅由 nginx 经 127.0.0.1 反代。

### 1.2 缓存定时清理（防磁盘撑爆）

kk 官方不清理转换产物（永久保留）。安装系统 cron，每天 03:10 删除 7 天前的产物：

```bash
cat > /etc/cron.d/kkfileview-clean <<'EOF'
# kkFileView 转换缓存清理:每天 03:10 删除 7 天未修改的转换产物,防止磁盘持续预警(删除后访问会自动重新转换)
SHELL=/bin/bash
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
10 3 * * * root docker exec kkfileview sh -c "find /opt/kkFileView-4.1.0/file -type f -mtime +7 -delete; find /opt/kkFileView-4.1.0/file -mindepth 1 -type d -empty -delete" >/tmp/kk-clean-cron.log 2>&1
EOF
```

### 1.3 客户已有 kk 服务时

跳过本节——只需客户保证 kk 地址对浏览器可达（同域反代或公网直连），在数据库参数中填完整外链即可（见第 3 节）。

## 2. 配置 nginx（子路径反代）

在项目站点 server 块中追加（参考 `server/nginx/pan.conf`）：

```nginx
# kkFileView 在线预览服务反代（容器以 KK_CONTEXT_PATH=/kkfileview 运行，URI 原样透传，不剥前缀）
# 经 80 暴露，不开放额外公网端口；kk 生成的绝对地址自带 /kkfileview 前缀，天然可达
location ^~ /kkfileview/ {
    proxy_pass http://127.0.0.1:8012;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```

要点：
- **`proxy_pass` 末尾严禁带斜杠**：带尾斜杠会剥掉 `/kkfileview/` 前缀，与 `KK_CONTEXT_PATH` 冲突导致 404。
- 生效：`docker exec nginx nginx -t && docker exec nginx nginx -s reload`（非容器部署则 `nginx -t && nginx -s reload`）。

## 3. 配置数据库（sys_config 系统参数）

后端启动时 `SysConfigCacheService` 扫描 `@MetaParam` 枚举（`OssParam.OSS_PREVIEW_URL`）**自动补插缺失参数**，默认值为 `0`（= 预览关闭），**无需手工 INSERT**。开启只需 UPDATE：

```sql
-- 查看（确认参数已自动注册）
SELECT config_key, config_value FROM sys_config WHERE config_key = 'OSS_PREVIEW_URL';

-- 方式 A：本机 nginx 反代相对路径（推荐，浏览器与 kk 同域，无跨域/防火墙问题）
UPDATE sys_config SET config_value = '/kkfileview/onlinePreview?url=' WHERE config_key = 'OSS_PREVIEW_URL';

-- 方式 B：客户 kk 独立部署的完整外链
UPDATE sys_config SET config_value = 'http://kk.客户域名.com:8012/onlinePreview?url=' WHERE config_key = 'OSS_PREVIEW_URL';

-- 关闭预览：置 0（或空）即可（kk 服务可保持常驻不受影响）
UPDATE sys_config SET config_value = '0' WHERE config_key = 'OSS_PREVIEW_URL';
```

修改后**重启后端生效**（`SysConfigCacheService` 启动时加载缓存）。

接口约定：`GET /web/oss/preview-url`（登录态），直接返回地址字符串，后端将 `0`/空归一为空串下发，前端仅需约定「空串 = 未开启」；未登录时统一响应包装 401 会话提示（HTTP 200）。

## 4. 前端接入

### 4.1 API 封装

```ts
// kkFileView 预览服务地址下发：由 OSS 模块通用接口提供（系统参数 OSS_PREVIEW_URL，所有项目共享）
// 返回空串表示未开启预览入口
export const getPreviewUrl = () => request(panApi('/oss/preview-url', 'GET'), {}, {}, false, false) as Promise<any>
```

### 4.2 组件接入（桌面端与移动端同模式）

```ts
/** kkFileView 预览服务地址：由后端配置下发（不同客户部署地址不同），为空表示服务端已关闭预览 */
const previewUrlBase = ref('')
const loadPreviewUrl = () =>
  getPreviewUrl()
    .then((res) => {
      previewUrlBase.value = String(res?.payload || '')
    })
    .catch(() => {})

onMounted(loadPreviewUrl)

/** 打开预览：前缀 + Base64(文件URL)；文件地址须为 kk 容器可访问的 http(s) 地址 */
const openPreview = (file) => {
  const url = getFileUrl(file.id, true)  // inline 短时效地址；其他项目用各自对象存储 getReadUrl(fileUrl, null)
  window.open(previewUrlBase.value + encodeURIComponent(btoa(unescape(encodeURIComponent(url)))))
}
```

模板：**必须以 `previewUrlBase` 为渲染条件**，参数未配置时预览入口不渲染：

```html
<a v-if="previewUrlBase && !record.isFolder && isPreviewable(record.name)" @click="openPreview(record)">预览</a>
```

参考实现：`view/src/views/pan/index.vue`（桌面操作列）、`view/src/views/pan/Mobile.vue`（移动端 rowClick 三分流：文件夹/预览/下载）。

### 4.3 其他项目接入清单

1. 后端引入 `framework/core/oss`（已引入的项目零后端改动，接口自动存在）
2. 前端照 4.1/4.2 接入（各项目按自己的 request 封装调整 api 写法）
3. 按第 1-3 节部署/指定 kk 服务并配置参数

```bash
# ① kk 直连（服务器上）—— 200
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8012/

# ③ 接口路由存在（未登录返回 200 且 body 包装 401 会话提示 = 路由在）

```

端到端：登录系统 → 网盘上传 docx → 点「预览」→ 弹出 kk 预览页（PDF 图片预览）。

## 6. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 预览按钮不显示 | 参数 `OSS_PREVIEW_URL` 为 0/空（默认关闭），按第 3 节配置并重启后端 |
| 预览页 404 | `proxy_pass` 带了尾斜杠剥掉前缀，或 `KK_CONTEXT_PATH` 与子路径不一致 |
| 预览页报"文件下载失败" | kk 容器访问不到文件地址（内网隔离/签名过期）；文件地址须为短时效 inline 预签名且及时访问 |
| 加密文档无法转换 | 转换类服务的固有限制，此类客户建议参数置 0 直接关闭预览 |
| 磁盘增长 | 1.2 节 cron 未安装或挂载点不在数据盘；清理产物无功能影响 |
