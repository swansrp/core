# 文档加工底座接入说明（tool/document）

M16 棒 3 下沉、修复轮（2026-10-21）定型的模块：**「用户上传的各种文件 → Markdown 正文」的单一正源**。
原先住在 `ai/llm` 的 `parse` 包（`FileMarkdownService` / `DocumentTranscriber` / `VisionModelConfig`）
与 `agent/FileMarkdownTool` 已整体搬进本模块，`ai/llm` 退回**纯模型层**——
依赖方向是**单向 `document → llm`**（本模块取 `ModelConfigProvider`，purpose=`VISION`）
＋**单向 `document → mineru`**（内置增强腿用 MinerU 客户端），反向有守卫测试
`ai/llm/src/test/java/com/bidr/llm/config/LlmLayeringGuardTest.java` 钉死。

## ① 一分钟最小样例

只要 Markdown 正文（绝大多数业务场景）：

```xml
<dependency>
    <groupId>com.bidr</groupId>
    <artifactId>document</artifactId>
    <version>${jarVersion}</version>
</dependency>
```

```java
@Autowired
private FileMarkdownService fileMarkdownService;

String md = fileMarkdownService.toMarkdown("D:/upload/合同.docx");   // 本地路径或 http(s) 自动识别
String md2 = fileMarkdownService.toMarkdown(inputStream, "清单.xlsx"); // 流传 InputStream 必须带文件名
String md3 = fileMarkdownService.toMarkdown(file, visionConfig);      // 显式指定多模态端点（最高优先级）
boolean ok = fileMarkdownService.isProcessable("a.pdf");              // 预检，不解析
```

要**路线留痕**（谁转的、有没有回落，审计/排障用）走 `DocumentProcessor`：

```java
DocumentArtifact artifact = documentProcessor.process(bytes, "扫描件.pdf", null, false);
String md = artifact.getMarkdown();
RouteTrace trace = artifact.getTrace();   // convertLeg / transcribeLeg / *Fallback / degradedNoPage
```

## ② 配置项

| 键 | 默认 | 说明 |
|---|---|---|
| `tool.document.transcriber` | 空 | 增强转录腿**选型键**，取值＝腿的 `legName()`（内置 MinerU 腿＝`mineru`）。三态见 ③ |
| `tool.document.max-file-size-bytes` | 104857600（100MB） | 单文件上限，超了拒（`IntakeStep` 内置实现执行） |
| `tool.document.max-vision-pages` | 50 | PDF 走多模态的页数上限，超出部分跳过并在正文注明 |
| `tool.document.render-dpi` | 150 | 扫描页渲染 PNG 的 DPI |
| `tool.document.min-text-per-page` | 20 | 某页提取文本少于这个字数＝判为扫描页 → 渲染 → 多模态转录 |

🔴 本模块**只读 Spring Environment，零 sys_config**（R-9）：选型键放 yml/`.env`，不进数据库参数页。
多模态端点（base-url / api-key / model-name / timeout）的三级回落口径仍在 `ai/llm`
（调用时显式传 → `VISION_*` sys_config → `llm.vision.*` yaml），见该模块 README 第 8 节。
MinerU 腿自己的配置面＝`mineru.*`（键面正源＝`tool/mineru/src/main/resources/mineru-config.template.yml`，
有 `MineruConfigTemplateCoverageTest` 做机器对账）。

## ③ 选型键的三态语义（别当成开关）

| `tool.document.transcriber` 取值 | 行为 |
|---|---|
| 空 / 未写 | 不装增强腿，直接走内置分派——**这是现网正常形态，不许抛** |
| 点名一个**没在装**的腿（如包没引、`mineru.enabled=false`） | WARN 一条"选型指向不存在的腿"＋走内置分派 |
| 点名一个**在装**的腿 | 该腿先被咨询；腿返回空或抛错 → WARN ＋回落内置，不拖垮解析 |

装配形状：每条腿自带 `@ConditionalOnProperty`（R-3），MinerU 腿在
`DocumentAutoConfiguration.MineruLegConfiguration` 内点名才装、且 `@ConditionalOnMissingBean(TranscribeStep.class)`；
业务要接别的转录引擎＝实现 `com.bidr.document.spi.TranscribeStep` 注册 Bean（自动装配让位）。

## ④ 内置分派（永驻 classpath、不参与选型、缺席不抛）

| 类型 | 处理 |
|---|---|
| md/txt/csv/json/xml/sql/yml/properties/log 等纯文本 | 直接读取（UTF-8 严格解码，失败回落 GBK） |
| html/htm | Jsoup 按语义转 Markdown（标题/列表/表格/代码块，剔除 script） |
| docx | POI XWPF：标题样式 → `#` 级标题，列表 → `-` 项，表格 → Markdown 表格 |
| xlsx/xls | POI：每 Sheet 一个 Markdown 表格，首行视为表头，单 Sheet 上限 1000 行 |
| pptx/ppt | POI：每页一个二级标题，文本框与表格按顺序输出 |
| doc | POI WordExtractor 纯文本提取 |
| pdf | PDFBox 逐页提取；某页文本过少判为扫描页 → 渲染 PNG → 多模态模型转录 |
| png/jpg/jpeg/gif/webp/bmp | 直接走多模态模型转录 |
| 未知扩展名 | 二进制检测（NUL 字节）：文本则按文本读，否则拒绝 |

office 输入 + convert 腿未装配 ＝原件直送并记 `CONVERT_FALLBACK`（老 doc 走 `LegacyOfficeExtractor`）。

## ⑤ 五槽 SPI 与「门面不接管什么」

流水线形状＝`IntakeStep`（限量取字节）→ `ConvertStep`（office→PDF，**只有外挂、无内置**）→
`TranscribeStep`（选型后的增强转录）→ 内置分派（兜底）→ `ArtifactStep`/`EnrichStep`（产物与后处理）。

| 门面**不接管** | 该谁做 |
|---|---|
| 文件的**存储与取回**（上传、对象存储、fileId→地址） | 业务侧 / `store` 族；本模块只吃 url／File／Path／InputStream／字节 |
| **任务编排**（排队、重试预算、状态机、进度） | `base/task` 与业务流水线；本模块是同步加工件 |
| **分块与入库**（切块、向量化、建索引） | 检索引擎侧（InkHub 走 WeKnora） |
| **落库/审计记账** | 业务切面；本模块只在产物里带 `RouteTrace` |
| 长任务的**异步提交/轮询** | `tool/mineru` 低层客户端（InkHub 自管预算）；本模块的腿是同步档 |

🔴 归属按族语义：本模块在 `tool/`（外部能力件），族界规则 `ai ↛ tool`——
所以 `document → llm` 合法、`llm → document` 禁止；`read_file` 工具也住本模块
（`com.bidr.document.agent.FileMarkdownTool`），能力目录登记在 `ai/agent-console`
的 `LlmCapabilityPackageConfig`（包名 `file-read`，工具名 `readFile`）。
因族界不能加依赖，工具名对账拆两处钉：agent-console 侧显式点名外族工具，真名反射对账腿在
`tool/document/src/test/java/com/bidr/document/agent/FileMarkdownToolTest.java`。

## ⑥ 常见坑

1. **同一条腿别打两遍**：外层流水线若已先咨询过同一引擎的异步腿，回落内置时必须传
   `process(bytes, name, vision, /* skipEnhancedTranscribe */ true)`（InkHub 的 `parseBuiltin` 腿即此用法）——
   该档只跳转录槽，convert 槽不受影响。
2. **`mineru.enabled=false` 是合法形态**：`MineruProperties` Bean 缺席 → 腿不装 → 走内置，全链不抛；
   消费方要用 `ObjectProvider<MineruProperties>` 吃这个语义（InkHub `MineruAsyncGateway` 即如此）。
3. **两档等待预算别混**：`mineru.max-wait-seconds`（默认 300）只服务同步门面/阻塞调用；
   后台流水线走低层客户端自管预算（InkHub 看 `inkhub.parse.mineru-max-wait-ms`），
   为后台链抬 `max-wait-seconds` 会把同步调用一起吊住。
4. **多模态端点没配 ≠ 解析坏了**：图片/扫描件在无 vision 配置时报的是"多模态配置缺失"，
   先按 ② 的三级回落逐级补，别去改分派逻辑。
5. **测试一律 JUnit5**：本模块 pom 钉了 `surefire-junit-platform`，写 JUnit4/TestNG 会被 provider
   选错造成 `Tests run: 0` 的假绿；JDK 8 下 `InputStream.readAllBytes()` 不可用。
6. **老口已撤**：`com.bidr.llm.parse.DocumentTranscriber` 不再存在，实现一律改 `spi.TranscribeStep`
   （`llm` 侧曾以 List 收口多条腿的历史判据已随入口一起搬到本模块）。
