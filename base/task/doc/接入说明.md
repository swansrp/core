# 异步任务底座接入说明（base/task）

> 一句话：**注解只把「执行侧的流程记账」变成声明式，受理侧与业务产物仍是你自己的代码。**
> 本模块提供注解三件（`@AsyncTaskType`/`@AsyncStage`/`StageOutcome`）＋底盘（受理落库、跑批抢占、
> 上下文重建、终态观察者、异常分诊、提交闸门）；它<b>不是</b>「整套异步框架不用写了」——
> 什么时候提交、业务产物落到哪，仍是业务代码。

## ① 一分钟最小样例

pom（一个类型三个阶段的最小接入只要这两处）：

```xml
<dependency>
    <groupId>com.bidr</groupId>
    <artifactId>base-task</artifactId>
    <version>${bidr.core.base-task.version}</version>
</dependency>
```

yml（可选——全部键有模块自带默认值，不配也能跑）：

```yaml
base:
  task:
    max-queue-ahead: 1000   # 提交闸门：同类型排队数超阈拒收（取不到排队数时放行）
```

流程类（执行侧：只写「这一步干什么」）：

```java
@AsyncTaskType(value = "PARSE", maxRetry = 3, leaseMs = 900_000)
@Service
public class ParseFlow {

    @AsyncStage(value = "FETCH_RAW", order = 1)
    public StageOutcome fetchRaw(SaAsyncTask task, AsyncStageScope scope) {
        return StageOutcome.to("CONVERT");            // 推进：落库由切面做
    }

    @AsyncStage(value = "CONVERT", order = 2)
    public StageOutcome convert(SaAsyncTask task, AsyncStageScope scope) {
        scope.snapshot("CONVERT_FALLBACK", json);     // 外部观测留痕：切面统一写
        return StageOutcome.pending(30_000);          // 本轮暂缓：原地不动，退避后再来
    }

    @AsyncStage(value = "TRANSCRIBE", order = 3)
    public StageOutcome transcribe(SaAsyncTask task, AsyncStageScope scope) {
        return StageOutcome.done();                   // 整任务完成：切面收口 SUCCESS＋通知观察者
    }
}
```

受理侧（业务自己写，注册即返回、不同步执行）：

```java
SaAsyncTask handle = asyncTaskService.submit("PARSE", bizRef, payloadJson, operator);
```

## ② 注解属性表

`@AsyncTaskType`（类级）：

| 属性 | 默认 | 说明 |
|---|---|---|
| `value` | —（必填） | 任务类型，落 `sa_async_task.task_type` |
| `maxRetry` | 3 | 重试预算：失败次数超过它即置 DEAD |
| `leaseMs` | 0＝跟 yml | 租约窗口；必须大于「最慢的单个阶段」而非轮询间隔（阶段跑完才续租） |
| `stageEnum` | 不启用 | 指到实现 `AsyncStageEnum` 的枚举类，复用 label 文案；进度仍按 order 推导 |

`@AsyncStage`（方法级，签名定死 `StageOutcome xxx(SaAsyncTask, AsyncStageScope)`）：

| 属性 | 默认 | 说明 |
|---|---|---|
| `value` | —（必填） | 阶段标识，落 `sa_async_task.stage` |
| `order` | —（必填） | 序号，**必须从 1 连续**：断号/重复＝**启动期直接失败**（进度按 order 推导，失真不可兜底） |
| `noRetryOn` | 空 | 命中即不重试的异常族（补 `RetryAware` 之外的口径），直接 DEAD |

yml 键（全部可选，缺省即「配了才出生」的反面＝自带默认）：

| 键 | 默认 | 说明 |
|---|---|---|
| `base.task.max-queue-ahead` | 1000 | 提交闸门：同类型可抢占排队数 ≥ 它即拒收；取不到排队数（查询失败）放行。负数＝关闸 |
| `base.task.lease-ms` | 900000 | 流程未指 `leaseMs` 时的租约缺省 |
| `base.task.runner.enabled` | true | 跑批开关（关掉后入队任务不被自动推进） |
| `base.task.runner.interval-ms` | 5000 | 跑批间隔（fixedDelay：跑完即睡，不叠轮） |
| `base.task.wake.enabled` | true | 提交即唤醒信号开关（它只是加速器，关掉由轮询兜底） |

🔴 只读 Spring Environment（`@Value`），不依赖 platform 的 sys_config（R-9）。

## ③ 三态返回契约（为什么不再是 boolean）

| 返回 | 落库效果 | 什么时候用 |
|---|---|---|
| `StageOutcome.to(下一阶段)` | stage 前进、RUNNING 不变、续租 | 这一步做完了、还有下一步 |
| `StageOutcome.to(当前阶段)` | stage 原地重写 | 合法形状（提交完把当前档再写一遍）；**order 更小则切面当场抛**（进度百分比单调） |
| `StageOutcome.pending(退避ms)` | stage 不动、`next_run_at` 后移 | 本轮没做完（外部引擎还在跑、队列积压）——「没做完」与「推进一步」从此是两种写法 |
| `StageOutcome.done()` | 末阶段＋SUCCESS＋清调度列＋通知观察者 | 整任务完成 |

现网的 `boolean` 里 `false` 同时表示「推进了」和「没推进」，是现网最容易读错的一行——
三态把这两种语义拆开。异常不属三态：直接抛，由切面分诊（下一段）。

## ④ 异常与重试预算

- 实现 `RetryAware.isRetryable()`（布尔两半，照 `OfficeConvertException` 形状）：
  `true`＝临时故障→FAILED＋退避（60s）、交给预算；`false`＝重跑结果不变→**直接 DEAD**。
- 未实现 `RetryAware` 的异常＝**默认可重试**——🔴 不做静默兜底：静默兜底会把「暂时没页」固化成
  「永远没页」，这是本模块必须保住的一条。
- `noRetryOn` 命中＝不可重试（不用改异常族）。
- 预算：失败次数（`attempt`）超过 `maxRetry` 即 DEAD；租约超时（实例失联）也计一次尝试并
  立即回队（失联不是业务失败，不吃退避）。
- 终态观察者：**SUCCESS／DEAD 必发、FAILED（仍在预算内）不发**——可重试失败每轮都进 FAILED，
  挂上去＝同一任务通知 N 次。原先写在执行侧 catch 里的业务失败态落库，**必须搬进观察者的
  DEAD 档**，不许留在阶段体。观察者抛异常不改任务终态。

## ⑤ 线程与上下文纪律

- **执行侧唯一入口＝跑批线程**：阶段方法只由 runner 执行；受理侧（`submit/begin/find/requeue`）
  不执行任何阶段。D15：本模块**没有同步执行口**，需要当场要结果的消费方走能力层同步门面。
- **业务禁在阶段方法里自行 bind/unbind 上下文**：`TaskContextBridge` 会从 `create_by` 重建操作人、
  经 `AsyncTaskContextContributor` SPI（业务实现）重建业务/租户上下文，整条链（含观察者）之后
  成对恢复。`AccountContext` 是每线程一格的 ThreadLocal、不认「是谁放的」——裸清在请求线程
  上会静默清掉登录态。
- **禁同类内部自调用**（`this.convert(...)` 不走代理，切面不接管＝什么都不写）。
- **跨阶段载体只有两个通用列**：`payload` 与 `external_id`（要传结构就经对象存储拿摘要串）；
  本模块不提供 ThreadLocal/内存黑板——那正是「进程重启就从头再来」要防的东西。
- **未标注零影响**：类上没有 `@AsyncTaskType` ⇒ 不注册、不生成任何行为。
- **幂等锁与显式作废是业务动作**：`scope.claimExternal(...)`（条件 UPDATE 当「同一件事只让
  一个人做」的锁）与受理侧 `requeue`/作废不属流程记账，仍由业务调用。

## ⑥ 常见坑

| 坑 | 症状 | 正解 |
|---|---|---|
| 阶段方法自带 `@Transactional` | 业务回滚把进度一起抹掉＝「任务从没跑过」→双实例重跑 | 切面已排在事务拦截器**外层**（`@Order(0)`），记账在业务事务之外独立落库；不要给切面改大到事务内层 |
| 注解打在实现类、调用经接口 | 切点漏继承（框架既有坑） | 注册表在目标类上解析注解；调用必须经 Spring 代理 Bean |
| 同类内部自调用 | `this.xxx(...)` 不走代理，什么都不写 | 阶段调用只从跑批入口进；业务侧不要直接调阶段方法 |
| 阶段 order 断号/重复 | 进度推导失真 | 首次收集（启动期 `@PostConstruct`）失败即启动失败（`TaskFlowRegistry` 构造抛 `IllegalStateException`），改好再起 |
| 受理侧忘了 `submit` | 没有任务行、跑批永远看不到 | `submit/begin/find/requeue` 是业务显式调用；同键 `(task_type, biz_ref)` 再 submit＝同一行 |
| 把 `submit` 返回值当业务产物用 | 长出「顺手把阶段跑完」的第二形态 | 句柄只含任务身份；业务产物落业务自己的表/存储 |
| 给业务表加 task_id 列 | 每次重开任务回写业务表 | 业务侧只存 `biz_ref`（幂等键即寻址正源），任务行由之推导 |
