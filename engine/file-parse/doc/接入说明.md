# engine/file-parse 接入说明

解析编排引擎（M17）：把「文件进来 → office 转 PDF → 解析 → 产物落 blob」沉成 core 的第一个
engine 族模块。业务只剩三件事：**submit ＋ 终态观察 ＋ 读产物**。

## 一、坐标与装配

- Maven：`com.bidr:engine-file-parse`（传递带 `base-task`/`store-blob`/`document`；🔴 不直接依赖
  `tool/mineru`/`tool/gotenberg`——腿装不装由 classpath 决定）。父仓 plsintec 钉版清单已收编
  （server/pom.xml dependencyManagement 的 plsintec profile）。
- 装配：`ParseEngineAutoConfiguration`（starter 风格），`engine.parse.enabled=false` 整体关闭
  （零装配）。缺省装配：`ParseEngineFlow`（任务类型 `PARSE`）＋产物落盘内置默认＋直通腿＋页图渲染器。
- 引擎不带自己的任务跑批——复用 `base/task` 的 `AsyncTaskRunner` tick+wake（已有消费方零新增配置）。

## 二、submit（提交一个解析任务）

```java
asyncTaskService.submit(ParseEngineFlow.TYPE /* "PARSE" */, bizRef, payload, operator);
// payload（引擎只认这三把键＋可选第四把；其余键只透传不解析，R-9）：
// {"sourceKey":"raw/{sha}.pdf", "fileName":"报告.docx", "variant":3
//  ,"artifacts":["markdown","pageMap"]   // 可选，D-11 裁剪键：闭集减法，缺省＝全集
// }
```

- `bizRef` 引擎不解释（业务幂等键，如 `parse:{fileId}:{versionId}`）；`variant` 是产物键代数段
  （文件轨＝业务版本号、材料轨＝0，D-1——引擎不当业务版本解释）。
- 受理闸门沿 `base.task.max-queue-ahead`（按类型），引擎不自建闸门。

## 三、终态观察（SUCCESS/DEAD 必发）

```java
@Component
public class MyParseObserver implements AsyncTaskObserver {
    public void onTerminal(SaAsyncTask task, AsyncTaskStatus status) {
        if (!ParseEngineFlow.TYPE.equals(task.getTaskType())) return;
        if (status == AsyncTaskStatus.SUCCESS) {
            // ARTIFACTS 快照（PERSIST 阶段落）＝交付通道：
            // { anchorSha, markdownKey, pageMapKey, imageCount, pageImageCount, route,
            //   pageCount, blockCount, requested, enrichLegs }
            String mdKey = jsonPath(task.getExternalSnapshot(), "markdownKey");
            // ① 回写业务行（如 parse_sha/page_map_key）；② 接力业务后段（如 ingest/summary）
        } else if (status == AsyncTaskStatus.DEAD) {
            // 业务失败态落库（引擎不认识业务行）
        }
    }
}
```

🔴 引擎 SUCCESS ≠ 业务 COMPLETED：可检索时点在业务后段完成之后；前端进度条按任务类型分轨。

## 四、读产物（键形正源＝BlobStore 八前缀）

`parsed/{sha}/v{n}.md`、`pagemap/{sha}/v{n}.json`、`convert/{sha}.pdf`、`image/{sha}/{name}`、
`thumb/{sha}/p{n}.png`（golden 由 `BlobKeyGoldenTest` 钉死，键形永不动）。正文里图片引用是
稳定占位（`BlobStore.imagePlaceholder`；scheme 是**业务协议值**、core 不内置字面量——配
`engine.parse.image-placeholder-scheme`，或自注册 `TextPassthroughService`/`ParseArtifactWriter`
Bean 注入自家常量，空＝装配快败），可访问 URL 由读取边缘现签。
进程外消费方（沙箱/脚本）零 Java：S3 增量 list `parsed/`＋`pagemap/` 前缀，sha256 对齐键。

## 五、腿与裁剪（能配什么）

| 键 | 缺省 | 语义 |
|---|---|---|
| `engine.parse.transcriber` | 空 | 异步转录腿选型：空＝第一条在装腿；`builtin`/`none`＝强制内置；配了腿不在＝WARN 走内置（三态，缺席不抛） |
| `engine.parse.mineru-max-wait-ms` | 3600000 | 外部引擎等待预算（3600 档，与同步门面 300 档分立） |
| `engine.parse.passthrough-remote-image-hosts` | 空 | 直通腿外链图片白名单（缺省一条不拉） |
| `engine.parse.image-placeholder-scheme` | 空 | 🔴 唯一必填：正文图片占位 scheme（协议值业务所有，空＝装配快败；替代给法＝自注册两内置 Bean 注入常量） |
| payload `artifacts` | 全集 | D-11 产物裁剪：本期唯一可减成员 `pageImage`（页图 PDFBox 逐页渲染）；子集-only，未知值/缺本体＝INTAKE 快败 |

**断点（D-2，正向）**：目标产物键已在＝秒级复用（重解析不重烧引擎）。**裁剪双向安全**：
裁剪先跑→全集任务补产缺失页图；全集先跑→裁剪任务断点秒级命中。

## 六、引擎不接管什么（边界表）

| 事项 | 归属 | 说明 |
|---|---|---|
| 受理闸门（要不要收这个文件） | 业务 | 扩展名白名单、空间/权限、秒传判定都是业务动作；引擎只答"给 key 能不能加工" |
| 业务状态行 | 业务 | `parse_status`/`parse_sha`/`page_map_key` 等列的写点在业务观察者（引擎 SUCCESS 后自快照回写） |
| 解析后段（入库/图注/摘要/归类） | 业务 | WeKnora/chunk/相似/归类是禁词（R-1）；业务自开 `parse-post` 类任务行接力 |
| 产物读控 | 桶凭据 | 产物键无空间维度＝内容寻址天然属性；读控走桶凭据不走业务行（D-9） |
| 阶段裁剪 | ❌ 永不 | R-10：无 skip-stage 开关；空转是缺省态（CONVERT 非白名单直通、ENRICH 不注册腿即空转） |
| 增强腿（ENRICH） | 业务注册 | 实现 `ParseEnrichLeg` 注册 Bean 即挂链；提示词等运营资产留业务 |
