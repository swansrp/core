# 站内信框架接入（base/notification 模块消费者指南）

> 面向**框架消费者**（宿主业务侧）："框架怎么用"。设计正源＝宿主立项册
> `docs/立项-M21-消息提醒机制.md`（十轮修订终态）；本文只写接入面。
> core 纪律：msg_type/action_type 值域全在业务侧，core 零业务常量；审计（base/audit）与
> 本模块互不依赖——审计记"谁做了什么"，站内信是"系统要告诉你什么"。

## 1. 模块与表

- 模块：`server/framework/core/base/notification`（artifactId `base-notification`，包 `com.bidr.notification`）。
- 表：`sa_notification`（core Schema 启动自动建表，**建表即冻结**）。一人一行＝写时扇开；
  `target_user`（ac_user.customer_number）即作用域；`tenant_id` 可空＝全局消息（信息列，
  **不进任何拦截器**）；业务上下文进 `extra` JSON。

## 2. 发消息：NotificationPublisher（唯一生产口）

```java
notificationPublisher.publish(NotificationDraft.builder()
        .msgType("FILE_PARSE_FAILED")                  // 业务枚举的 code（core 只当字符串）
        .level(NotificationLevel.ERROR)
        .title("《" + name + "》解析失败")
        .summary(NotificationText.humanReason(task.getError(), 300))   // 去堆栈截 300
        .targetUser(task.getCreateBy())                // 收件人；多收件人用 .receivers(list)
        .tenantId(tenantOf(file))                      // 可空＝全局；归属取自业务对象
        .action(FileNotificationAction.FILE_PREVIEW.code(), "fileId", fileId)
        .actionParam("versionId", versionId)
        .dedupeKey("PARSE:" + fileId + ":" + versionId)
        .extra("spaceId", spaceId)                     // 业务上下文 JSON
        .build());
```

- **绝不抛**：publish 内部 try-catch＋log.error（同审计 writer 纪律）——提示失败不许变成业务二次失败。
- **写腿 REQUIRES_NEW**：`@Transactional` 业务里 catch→publish→rethrow，提醒不随业务回滚被吞。
- **action 五条校验**（违规只丢动作、消息照发）：码 `^[a-z][a-z0-9_.-]{0,63}$`；键
  `^[a-zA-Z][a-zA-Z0-9_]{0,31}$`；值只收 String/Number/Boolean（拒嵌套）；≤10 键；序列化 ≤1000 字符。
- **dedupe**：同 target_user＋dedupe_key＋未读＝只更新不新增；已读后再失败＝新行。
- **开关**：sys_config `notification.async-task.enabled`（缺省开）、`notification.mute-types`
  （黑名单）——读不到配置按缺省（开/不静音），配置项不存在不会抛。

## 3. 异步任务失败→消息：桥＋Resolver

```java
public interface NotificationContentResolver {
    boolean supports(String taskType);              // 例：PARSE / parse-post
    Optional<NotificationDraft> resolve(SaAsyncTask task, AsyncTaskStatus status);
}
```

- `AsyncTaskNotificationBridge`（core 自动收集）只监听 **onTerminal 的 DEAD**——预算内
  FAILED 正在退避（发了就是同一任务刷 N 次）、SUCCESS 产物列表可见，都不发。
- 触发纪律逐条见立项册 4.2 触发矩阵：材料轨 `parse:material:` 跳过；`llm==null` 这类
  配置态不发；摘要失败一期不发。
- resolver 内**异步线程没有 TenantContext**（TaskContextBridge 只重建 AccountContext）——
  租户归属从业务对象推导（如 `KbFile.spaceId → KbSpace.tenantId`），推不出就 null＝全局可见。

## 4. 存取 SPI：NotificationStore（宿主可覆盖）

```java
public interface NotificationStore {
    void save(List<NotificationRecord> rows);      // 已按收件人扇开；写腿 REQUIRES_NEW
    NotificationPage page(String receiver, long current, long size, String readFlag);
    long unreadCount(String receiver);
    boolean markRead(List<Long> ids, String receiver);
    boolean markAllRead(String receiver);
}
```

- **默认实现** `SaNotificationStore`（表 `sa_notification`）：宿主实现本接口即覆盖
  （`@ConditionalOnMissingBean`）；只用默认时不需任何配置，`notification.store.enabled=false`
  可关掉默认实现与建表。
- 🔴 **实现契约**：①所有读写 receiver 恒为登录人（服务端 `AccountContext` 取，不接受参数）；
  ②`markRead` 强制 `target_user=登录人`＋`read_flag='0'`（越权/幂等双闸）；③`page` 返回
  core `NotificationPage`（**不返回 MP Page**——控制器不再强转，宿主实现不会 CCE）。
- **租户恒定过滤**（默认实现内置）：`tenant_id IS NULL OR tenant_id IN (TenantContext 集合)`，
  空集合退化只看 NULL——不写裸 `=`，不靠拦截器。

## 5. 消费端（API ＋ 铃铛）

- 通用 4 端点：`GET /web/api/notification/{list,unread-count}`、`POST .../read`、`.../read-all`。
  🔴 receiver 恒取登录人、**不继承 BaseAdminController**（防 /general/query 查他人消息）。
- **SSE**：`GET /web/api/notification/stream`（M18 同款 fetch 手动 Bearer）——事件
  `connected`（通道就绪）/`notification`（有新消息，前端刷新未读）；15s 心跳；多实例须改
  Redis 广播（单实例内存注册表）。
- **铃铛**：`framework/components/common/notification/NotificationBell.vue`（纯展示，props/emits）
  ＋宿主接线壳（InkHub＝`components/NotificationBellEntry.vue`：探测/SSE 订阅/路由解析）。
  显隐判据＝**SSE 建连**：能连上才显示；首连失败（404/断开/非事件流）＝12h 静默窗自隐且不降级
  轮询；曾连上后断流＝降级轮询，下次路由切换重试 SSE。
- **动作解析表在业务侧**（框架件不认路由）：`ACTION_ROUTES: actionType → (params) => RouteLocationRaw | null`；
  未知 actionType＝只标已读不跳转；params 只放 id/枚举；点击后目标页重新鉴权。

## 6. 职责速查

| 场景 | 用什么 |
|---|---|
| 任务死透提醒（解析失败等） | `NotificationContentResolver` bean（桥自动收集） |
| 同步失败即时提醒（上传失败等） | catch 里 `NotificationPublisher.publish` → rethrow |
| 发消息动作可点击 | draft `.action(code, key, value)` ＋前端 ACTION_ROUTES 加一行 |
| 宿主用自己的消息表 | 实现 `NotificationStore`（租户纪律内聚在实现里） |
| 不想要默认表 | `notification.store.enabled=false` |
| 审计（谁做了什么） | base/audit 的 `@AuditTrail`（另一套，见其接入文档） |
