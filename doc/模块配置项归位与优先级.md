# 模块配置项归位与优先级（yml ↔ sys_config）

一句话规则：**环境绑定的值（地址/账号/口令/Key/代理）与"切了会让历史读错路"的键只进 yml；运行期该热调的阈值/开关进 sys_config 参数页；两处同名的键，取值链一律＝库值非空白优先 → yml 回落 → 出厂缺省**（库值留空＝"未表态"，不是"关闭"）。

> 本表与 project-setup skill 的 `assets/module-docs/`（setup 向导正源）同步维护；键面以 core 各模块自带的 `*-config.template.yml` ＋ `*ConfigTemplateCoverageTest` 机器对账为准。

## 二、为什么这样切

- **只留 yml、刻意不进参数页的两类**：① 环境绑定项（密钥、代理主机——不该在管理页露面）；② 切换会让已有会话/历史读错路的键（如 `agent.runtime.provider`，必须伴随重启）。
- **进 sys_config 的判据**：运营期要热调、且改错不炸链路（阈值、预算、开关）。core 种子按 `@MetaParam` 枚举缺省回种——**只插不删**，改缺省值救不了已建库，所以出厂值一律留空＝未表态。
- **两类 0 语义别混**：开关键 0＝关闭机制；闸门键 0/非法＝回落保守默认（运维填 0 反而拿回最大上限）。

## 三、落盘纪律

1. 🔴 **profile 落点**：开关/模式/安全语义类键必须写进部署实际生效的 profile yml（通常是 `application-pre.yml`，用 prod 再写一份）——只写 dev 等于部署档没配。
2. 🔴 **敏感值形态**：yml 一律 `${KEY:}` 占位；core 模板实际值放 `server/.env`（git 排除、relaxed binding 注入），framework 型无 `.env`、由 Jenkins/启动参数注入同名环境变量。
3. 🔴 **同名共存键的读取点必须单源**（如 `AgentRuntimeConfigProvider`、`LoginServiceImpl#resolveRegisterMode`），同一进程两条腿各按各的选型读＝事故。
