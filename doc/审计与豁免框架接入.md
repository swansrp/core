# 审计与豁免框架接入（authorization 模块消费者指南）

> 面向**框架消费者**（宿主业务侧）："框架怎么用"。机制裁定与设计史正源＝erp 仓
> `server/docs/adr/0001-tenant-exemption-and-audit-trail.md`（ADR 0001）；本文不重复裁定论证。
> core 纪律：本文涉及的全部件零 biz_* 依赖——落库、身份升格都由宿主装 SPI 实现，core 只定义契约。

## 1. @AuditTrail 审计注解

`com.bidr.authorization.audit.AuditTrail`（METHOD 级，RUNTIME）。标注在业务方法上，方法**成功返回后**
由 `AuditTrailAspect` 组装 `AuditRecord` 写入 `AuditTrailSink`。

| 属性 | 落列 | 说明 |
|---|---|---|
| `bizType()` | `biz_type` | 业务域裸码，宿主自定取值域（必填） |
| `action()` | `action` | 动作裸码（必填） |
| `field()` | `field_name` | 变更列名；无列语义的动作留空（缺省 ""） |
| `bizId()` | `biz_id` | **整体 SpEL 表达式**（见 §2），求值结果转 String |
| `reason()` | `reason` | **`#{...}` 模板**＋SpEL 插值；纯文本原样落列 |
| `operatorIdentity()` | `operator_identity` | 操作身份字面量（staff/merchant/platform 之类，宿主定值域） |

注解**不设**的列（框架固定来源，属性通道不存在）：

- `operator_user_id`＝`AccountContext.getOperator()`（切面硬编码）；
- `old_value`/`new_value`＝`AuditContext` 两个约定键（见 §3）；
- `tenant_id`＝`TenantContext.currentTenantId()`，由 sink 实现决定最终落列值（见 §4）；
- `occurred_at`＝组装时刻服务端钟。

触发与不触发：

- 方法**成功返回**后产一行审计；方法抛业务异常＝不产行（异常原样上抛，审计侧不介入、不告警）。
- 注解只在**Spring bean 外部调用**时生效（AOP 代理语义）：同类内部调用/私有方法不拦截——
  多行审计、幂等早退路径、私有共享腿等"方法边界与审计行不对齐"的场景，**走 §4 的 sink 直调
  （programmatic）而不是硬凑注解**（ADR 0001 §5.1 的四调用点取证即此类）。

## 2. SpEL 变量面

求值时机＝@Around proceed **返回之后**（`#result` 因此可用）；求值失败＝本次审计行丢弃＋
log.error＋告警（不炸业务）。

| 变量 | 含义 |
|---|---|
| `#参数名` | 方法入参按名引用（编译带 debug 信息时经参数名发现器解析；解析不到时用 `#a0`..`#aN` 按位兜底） |
| `#result` | 方法返回值（null 时不可用） |
| `#args` | 入参数组（`#args[0]` 按位） |
| `#ctx` | `AuditContext` 快照 Map（方法体内 put 的运行时上下文） |

```java
@AuditTrail(bizType = "merchant_profile", action = "change", field = "grade",
            bizId = "#profileId",
            reason = "调整等级 #{#profileId}：#{#ctx.get('oldValue')} → #{#result}")
public String changeGrade(Long profileId) { ... }
```

## 3. AuditContext 约定

`com.bidr.authorization.audit.AuditContext`（ThreadLocal 逃生口）：注解写不下的运行时值
（查库才知道的旧值/流水号等）在方法体内 `put`，切面组装时暴露给 SpEL（`#ctx.get('key')`）。

- **约定键**：`AuditContext.OLD_VALUE`（"oldValue"）与 `AuditContext.NEW_VALUE`（"newValue"）
  会被切面**自动并入** `old_value`/`new_value` 两列，不必再经 SpEL 引用。
- **生命周期**：方法作用域——切面在被注方法 finally 里 `clear()`；请求线程侧另有
  `AuthInterceptor#afterCompletion` 兜底清理（覆盖"注解方法被内部调用、切面不生效"的盲区残留）。
  Tomcat 线程复用，污染即串档——用完即弃、不跨方法假设残留。
- **嵌套口径（实现取简）**：嵌套审计方法共享同一线程上下文，最内层收尾即整表清空；需要更复杂
  分层的场景走 sink 直调（programmatic）而非注解。

## 4. AuditTrailSink 实现契约（宿主职责）

`com.bidr.authorization.audit.AuditTrailSink`（core 定义、业务装实现——`LoginFillTokenInf`/
`TenantExemptIdentityFill` 同族 SPI）：

```java
public interface AuditTrailSink {
    void write(AuditRecord record);
}
```

- **收集方式**：切面经 `ObjectProvider` 可选收集全部实现，按 Spring `@Order` 顺序逐个调用；
  单个实现失败不影响其余实现继续写。**宿主无实现＝审计行丢弃**＋log.error＋运维告警（不抛、不影响业务）。
- **异常语义**：实现内抛出的任何异常都会被切面吞并（log.error＋告警、业务不受影响），但会丢审计行
  ——实现方应自行兜好落库故障；**实现方不要再吞一次、不要再告警一次**（erp 参考实现
  `ErpAuditTrailSink` 的"不吞二次"纪律）。
- **执行时机**：业务方法返回后的**同线程同步段**——勿做重活/阻塞，勿读取 ThreadLocal 之外的请求态假设。
- **落库自由度**：core 对落库表零感知（`AuditRecord` 只做列名对照，零 biz_* import）。宿主实现里
  自行处理表选择、豁免包裹、租户回填——erp 参考实现把"审计写天生跨租户/无租户"的豁免段
  （`TenantContext.runWithoutIsolation` 包裹 insert）**内聚在 sink 写入点**，调用方零豁免负担；
  tenant_id 回填规则＝载体显式值优先、空则回填当前租户（详见 ADR 0001 §5.2）。
- **简单场景优先走注解，复杂场景走 sink 直调**：启用注解的三个条件——方法边界与审计行对齐
  （一方法一行、无幂等早退静默路径）、操作人与租户可由 `AccountContext`/`TenantContext` 表达、
  无私有共享腿。不满足就组装 `AuditRecord` 直调注入的 sink，语义等价且无 AOP 盲区。

## 5. @CrossTenant 入口级读豁免

`com.bidr.authorization.tenant.CrossTenant`（METHOD+TYPE，RUNTIME；0.4b 于业务侧引入，
2026-10-24 迁 core——ADR 0001 裁定 5 终裁）。

- **标注**：方法或类（**方法优先、类兜底**）。消费在 `AuthInterceptor` 鉴权链：`validateAuth`
  **之后**执行（鉴权失败抛错绝不会置位豁免＝fail-closed）——命中即置平台档
  （`TenantContext.markPlatform()`）＋WARN 留痕（uri/handler/operator，不打印租户值）＋SPI 回调，
  行级隔离器对隔离表不拼 `tenant_id`（读侧豁免）。
- **身份升格 SPI**：`com.bidr.authorization.tenant.TenantExemptIdentityFill`（`void fill()`）——
  core 定义、宿主实现（@Component 即被回调；经 `ObjectProvider` 可选收集，宿主无实现时框架面
  照常置位平台档）。宿主在此升格自己的身份上下文（erp 侧＝注入 PLATFORM 身份三键并清租户/店键；
  业务键是业务单一正源，core 不代写）。
- 🔴 **读写边界（ADR 0001 裁定 1，防"标了就能写"的误用）**：本注解**只豁免读侧**——写闸
  （`TenantIsolationFillHandler`）只认 `runWithoutIsolation` 包裹段，不认平台档。本端点内写隔离表
  仍需显式 `runWithoutIsolation` 包裹；有当前租户时写闸 autofill 本就会自动补值，无需豁免。
- **清理**：平台档请求收尾复用 `afterCompletion` 既有 `TenantContext.remove()`，宿主零新增清理点。
- **与 `@Auth(AuthAdmin)` 分工（裁定 5，互补不互替）**：AuthAdmin＝**权限＋豁免绑定**（仅平台
  管理员可进，进即平台档）；@CrossTenant＝**豁免独立于权限档**（不限定调用者身份，端点自己声明
  "我是跨租户读面"）——"非平台管理员需要跨租户视图"的端点出现时用后者，权限对不上 AuthAdmin。

## 6. 场景速查

| 场景 | 用什么 |
|---|---|
| 审计一行、方法边界对齐、上下文可表达 | `@AuditTrail`（§1–§3） |
| 审计多行/幂等早退不产行/私有腿/匿名链（无 AccountContext） | 组装 `AuditRecord` 直调 `AuditTrailSink`（§4） |
| 审计落库本身 | 必须经 sink 实现——豁免内聚在写入点，调用方不手写豁免包裹 |
| 平台管理员跨租户读端点 | `@Auth(AuthAdmin)` |
| 非平台管理员跨租户读端点 | `@CrossTenant`（只豁免读侧） |
| 代码段级豁免/写隔离表 | `TenantContext.runWithoutIsolation`（唯一写侧显式通道） |
